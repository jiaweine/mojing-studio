# 墨境 · 产品与交互说明

## 1. 产品定义

墨境是一套面向长篇网络小说作者、工作室和内容团队的对话式创作空间。

产品目标不是让作者“学习怎么使用 AI”，而是让作者像和一个长期合作、记得整本书的编辑团队沟通一样工作。作者提供目标、取舍和审美判断；系统负责把作品状态整理好，把相关旧事找回来，把一章从设计、写作、检查、返工到保存完整做完。

## 2. 首要体验原则

### 作者看到创作，不看到后台机制

页面可见语言只使用：

- 作品
- 章节
- 人物
- 线索
- 设定
- 素材
- 创作进度
- 创作引擎
- 剧情规划
- 正文主笔
- 校对与体检
- 参考图理解

后台执行结构、内部角色、模型协议、工具调用、检查点等概念不出现在客户页面。

### 对话是主入口

任何核心动作都应该能通过自然语言完成，而不是要求用户先找到某个管理页面。

典型请求：

```text
开一本都市重生，主角最想补救的是妹妹的死。
继续下一章。
接下来三章不要揭反派身份。
重写第46章，让人物选择更痛，但别改坏第80章的关系。
规划后100章，最近20章细一点。
查一下钥匙第一次发热是哪一章。
帮我看看最近30章是不是越来越像同一种桥段。
```

## 3. 桌面信息架构

桌面采用三栏，而不是后台管理台式多页面导航。

### 左：作品书架

只承担：

- 新建作品；
- 切换作品；
- 显示题材、当前章与整体进度；
- 打开创作引擎。

### 中：长期对话与正文工作区

这是产品的视觉中心。

空状态提供不等宽的四个起点：

- 继续下一章（主操作）
- 规划后续
- 作品体检
- 重新梳理

主操作明显更大，其余入口作为辅助命令，不使用“四张等宽 SaaS 卡片”。

对话发生后，消息区使用更接近稿纸的阅读排版，正文信息优先于装饰。

### 右：作品资料

六个固定页签：

- 章节
- 人物
- 线索
- 设定
- 素材
- 记录

右侧不是数据驾驶舱。内容主要靠字号、分组、细分隔线和留白建立层级，避免卡片套卡片。

## 4. 移动端

移动端不强行保留三栏。

默认进入“专注正文”：

- 顶部：品牌、作品名、资料、创作引擎；
- 中间：对话和正文；
- 底部：创作输入。

点“资料”后，章节/人物/线索等以全屏层出现；按钮变成“返回正文”。

目标是手机上可以继续讨论、补要求、查看资料和做轻创作，不假装手机能提供和桌面完全相同的信息密度。

## 5. 运行中补充要求

长正文可能需要较长时间。输入框不能因为系统正在工作就完全锁死。

当正在执行可安全接入的长任务时，作者仍可发送一句补充，例如：

```text
这章不要让周岚出现。
保留原稿里“钟声停了”那句。
不要现在解释钥匙来源。
```

页面提示“补充要求已收到”，后台在下一个安全阶段吸收。

对于已经接近结束、没有安全接入点的快速任务，应明确让用户作为下一条消息发送，而不是显示“已收到”却实际忽略。

## 6. 未完成创作

如果任务真正失败、服务中断，或重启后留下未完成运行，记录页显示一张简洁卡：

```text
上一次创作没有完成
已经保存的内容不会重复保存。
[继续完成]
```

不向作者展示“检查点”“任务节点”“恢复状态机”等内部实现。

如果已经到“内容准备好、只差提交”的安全阶段，继续完成应直接落盘，避免重新生成造成文本漂移。

## 7. 创作引擎设置

设置弹窗只暴露作者能理解并真正影响作品的选项：

- 已连接服务
- 剧情规划
- 正文主笔
- 校对与体检
- 参考图理解
- 章节质量线
- 最多整章重写
- 创作深度
- 关键章节双重检查

“创作深度”是用户产品概念，不解释后台具体会增加多少内部任务。

## 8. 多模态体验

用户可以把以下内容直接拖进聊天：

- 人物参考图
- 场景/建筑/服装图
- 地图
- 封面灵感
- PDF 世界观资料
- TXT / Markdown 笔记
- CSV 表格
- JSON 设定数据

消息历史必须保留文件卡，不能出现“后台用了，但聊天里看不见刚发过什么”的情况。

图片进入创作后被转成可复用视觉笔记，目标不是机械复述“图中有什么”，而是形成可以反复用于小说描述的稳定辨识点。

## 9. 视觉方向

定位：**出版社编辑台 × 当代长篇写作工具**，不是“AI 控制中心”。

当前设计参数：

- 版式变化：6 / 10
- 动效强度：4 / 10
- 信息密度：5 / 10

视觉语言：

- 深墨左侧书架；
- 冷白纸张主舞台；
- 单一朱红强调色；
- 正文区域用宋体/衬线阅读气质，操作区域用系统中文无衬线；
- 细边界、更多排版分层，少用浮起的独立卡片；
- 不使用紫蓝科技渐变；
- 不使用通用 Inter + slate SaaS 模板；
- 不做卡片套卡片；
- 不用每个标题上方都放圆角图标块；
- 不做无意义的循环发光、脉冲和背景动画。

动效只服务三类状态：

1. 弹层进入/退出；
2. 创作进度状态变化；
3. 内容保存/资料加入后的短反馈。

`prefers-reduced-motion` 下关闭非必要动效。

## 10. 成功标准

一名第一次打开产品的作者应该在一分钟内完成：

1. 新建一本书；
2. 说一句话开始讨论或写作；
3. 看懂当前正在发生什么；
4. 找到写好的章节；
5. 找到人物/线索/设定；
6. 在任务进行中补一句要求；
7. 不需要理解任何后台术语。
